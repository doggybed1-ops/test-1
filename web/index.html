    UNDER THE HOOD · ENGINEERING PREVIEW

    Protection with a compiler
    at its core.

    VEIL parses your source into a Lua abstract syntax tree, tracks scopes, and transforms the supported program before generating a fresh build. This engineering preview implements a defined compatibility subset; commercial protection parity has not been established.

    01 Parse & validate02 Transform the AST03 Encode constants04 Virtualize · Maximum05 Validate output syntax

    What Maximum adds

    Supported instructions compile to a custom register VM. Opcode mappings and instruction operands vary between builds. The runtime supports lexical closures and shared upvalue cells.

    Compatibility boundaries

    Maximum excludes weak and closing metatables (__mode, __close), explicit collectgarbage, and Luau generalized iteration over tables or __iter. Use function iterators such as pairs and ipairs. Source profiles preserve native generalized iteration.

    All profiles exclude debug and environment introspection, function-bytecode reflection, and Lua 5.1 legacy implicit arg bindings in variadic functions. Stack traces, function environments, and timing can change.

    Validation

    Submitted source is never executed by the public API. Builds receive syntax validation; behavioral regression checks run in the project's isolated test suite. Obfuscation raises the cost of source inspection; it cannot make client-side code unrecoverable.
    DOCUMENTATION

    A little context.
    A better build.

    1 / Choose the target runtime

    Lua 5.1 syntax is the baseline. Lua 5.2–5.4 and Roblox Luau profiles target their Lua 5.1-compatible subset. Version-specific operators, goto, Luau types, continue, and compound assignments are rejected. Luau output can run inside Roblox, but Roblox APIs are available only in the Roblox environment.

    2 / Pick a protection level

    Standard transforms identifiers and literals. Advanced adds control-flow transformations and opaque predicates. Maximum adds the custom virtual machine. Individual switches configure supported passes; the build manifest reports what actually ran. This is an engineering preview with a scoped compatibility contract.

    3 / Compile, then verify in your runtime

    Paste a module or drop a UTF-8 .lua or .txt file of up to 512 KiB. Use the compile button or Ctrl + Enter. Output syntax is checked on the server. Copy or download the result, and test its behavior in your application before distributing it.

    Runtime limitations · all profiles

    Ordinary functions, closures, tables, metatables, loops, and varargs are supported within the implemented subset. Debug APIs, environment introspection, and function-bytecode reflection such as string.dump are unsupported. Lua 5.1's legacy implicit arg binding in variadic functions is unsupported; use select and explicit ... instead. Do not rely on source locations or exact timing.

    Additional Maximum exclusions

    The VM retains references in virtual registers, so weak tables (__mode), closing metatables (__close), and explicit garbage collection with collectgarbage are outside its equivalence guarantee. VM protection also changes stack frames and generated function environments.

    Luau generalized iteration over a table or through __iter is unsupported in Maximum. Use pairs, ipairs, or a function iterator. Known table iterators are rejected during compilation; dynamic iterator values receive a runtime function check. Standard and Advanced preserve native generalized table iteration in the Luau runtime.

    Detected unsupported syntax and recognized restricted forms return explicit errors. Dynamic aliases cannot always be detected statically; scripts must stay within these documented limits.

    Builds & errors

    Each build uses fresh randomness. An error includes a code and source location where available. Source and output size limits, rate limits, and compiler timeouts keep requests bounded. An error never counts as a completed build.
    SOURCE PRIVACY

    Your source is
    your business.

    Code is sent to the configured compiler service when you select Obfuscate. The service processes source in memory and does not intentionally persist request source or generated output. This workbench does not store your code in browser local storage.

    The public API compiles source without running it. Logs contain request identifiers and error metadata rather than script bodies. Hosting providers may retain infrastructure access logs according to their own policies.

    Downloaded scripts stay on your device. Reloading this page clears the editor session.
